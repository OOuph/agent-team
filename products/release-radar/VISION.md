## Что это
`releases.formachines.ai` — ежедневная читаемая лента релизов ≈ 100 отслеживаемых пакетов PyPI и npm (seed-список Errata + популярные SDK, фреймворки и инструменты): пакет · версия · дата · флаг «в release notes есть breaking / deprecated / removed / renamed / dropped support / no longer» с **дословной цитатой 1–2 строк** из первоисточника · ссылка на release notes · бейдж «есть проверенная правка в Errata», если пакет есть в `formachines.ai/errata/index.json`. Для разработчиков, которые обновляют зависимости и спрашивают «что сломалось».

## Для кого и зачем
| Пользователь | Приходит с | Получает | Успех |
|---|---|---|---|
| Разработчик Python/JS, обновляющий зависимости | «что сломалось в новой версии X?» | карточку релиза с дословной цитатой про breaking и ссылку на release notes | внешний клик на release notes через `/go/<id>/` |
| Пользователь кодинг-агента (Claude Code / Cursor / Codex) | ошибка после обновления пакета | бейдж Errata → страницу с проверенной правкой | клик на запись Errata; запрос `/pkg/<eco>/<name>/index.json` |
| Мейнтейнер из seed-списка | проверить, как его релиз читается снаружи | страницу пакета `/pkg/<eco>/<name>/` с историей за 7 дней | возврат; ссылка на нас из changelog |
| Автор дайджестов / бот-агрегатор | нужен структурированный источник | `/today.json`, `/feed.xml`, `/llms.txt` | регулярные запросы JSON/RSS не от известных краулеров |

## Что обещаем и чего не обещаем
- На каждой странице: «Built by AI agents (agent-team) without human editing · responsible: Dmitry, formachines.ai · updated <UTC>». Никакого сбора персональных данных, форм, трекинга людей; JavaScript на сайте отсутствует.
- Адреса страниц не меняются: `/`, `/pkg/<eco>/<name>/`, `/pkg/<eco>/<name>/index.json`, `/today.json`, `/feed.xml`, `/llms.txt`, `/go/<id>/`, `/legal/`. Данные датированы (время сборки на каждой странице, дата релиза у каждой карточки); источник каждого числа назван (реестр, GitHub Releases, Errata).
- Флаг «breaking» — только совпадение регулярного выражения в тексте release notes плюс дословная цитата; цитата присутствует в первоисточнике слово в слово и ведёт на него ссылкой.
- Чего не делаем: **никакого LLM-суждения о breaking** (ни пересказа, ни «вероятно ломает», ни резюме changelog) — на главной и в постах только регэксп + цитата; **не републикуем changelog целиком** — ≤ 3 цитаты на релиз, каждая ≤ 280 символов, всегда со ссылкой; не пишем о моделях (second screen Errata — только по пакетам: дата последней перепроверки, не «устарел»); не показываем «устарел» без даты перепроверки; не используем внешние шрифты, пиксели, встраивания.
- Честно показываем, что записей Errata мало (19 пакетов на 02.11): бейдж есть у немногих, и это нормально.

## Ежедневная работа команды
- **Пересборка 06:00 UTC** (cron на сервере, не на Mac): `python3 build.py` → опрос реестров → новые версии за 7 дней → release notes с GitHub (токен владельца в `.env`, без него лимит 60/ч и половина notes не выкачается) → регэксп → статика в `public/` → коммит в `main` → droplet публикует за ≤ 5 мин. **День без пересборки = дефект** (на главной стоит дата сборки; если она старше 30 ч — задача P0).
- **Тихий день:** если за 24 ч ни одного релиза — блок «recent» расширяется до 48 ч и говорит об этом; 7-дневные списки рендерятся всегда; главная никогда не пустая.
- **QA (ревьюер) каждый день:** у каждого релиза есть ссылка и дата; цитата присутствует в первоисточнике дословно (`data/github/<repo>.json`); бейдж Errata ведёт на живую запись; `build.json` без ошибок; 375 px без горизонтальной прокрутки.
- **Аналитик:** какие `/pkg/*` читают, клики по `/go/*`, запросы `/today.json` и `/feed.xml` не-браузерными UA, 404 на `/pkg/<x>/` (= спрос на пакет), внешние referer.
- **PO:** добавление пакетов по 404 и по referer (одна строка в `config/packages.txt`); правка `config/ignore_patterns.txt` по подтверждённым ложным срабатываниям; задачи разработчику только из этого файла и наблюдений аналитика.
- **Маркетолог:** ежедневная карточка «вышло N релизов, M с breaking» в Telegram и Mastodon (с цитатой и ссылкой на сайт), еженедельный свод на dev.to; тест формата поста (с кодом / без, время). Каждый пост — с подписью ИИ-агента.
- **Разработчик:** одна задача за цикл в репозитории сайта, коммит на ветку задачи с собранным `public/`; никаких новых зависимостей (только stdlib Python 3.12).
