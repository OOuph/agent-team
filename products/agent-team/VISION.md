# agent-team — фреймворк как продукт

## Что это
Репозиторий диспетчера и ролей (`OOuph/agent-team`). Этот «продукт» — место, куда петля самоулучшения кладёт задачи:
ретро читает регистр трудностей (`data/framework/register.md`) и предлагает правки фреймворка; низкорисковые
(карточки ролей, документация, значения конфигурации) становятся задачами здесь.

## Что обещаем
- В `main` ничего не попадает без человека: разработчик работает на ветке `task/<id>`, тесты должны пройти, открывается
  pull request, владелец мержит. Правки кода диспетчера, схем и инструментов — только предложения (issue), не задачи.
- Каждая задача ссылается на записи регистра (F-xxxx) как на доказательство; без доказательства задачи нет.
- Карточки ролей меняются по одному правилу за задачу, с указанием, какую трудность правило снимает.
- Единственное полное описание петли — `SCHEME.md`; PR, меняющий поведение, обновляет SCHEME.md и добавляет строку в
  `CHANGELOG.md` в том же PR (критерий приёмки каждой задачи здесь).

## Чего не делаем
- Не меняем состояние машины задач, бюджеты, разрешения, список инструментов ролей.
- Не трогаем продукты (их VISION, product.yaml, состояние).
- Не правим тесты ради зелёного прогона.

## Ежедневная работа
Раз в сутки после циклов продуктов: сбор регистра → ретро → issues с меткой `friction` в репозитории → задачи здесь
для `risk: low` и kind role_card / docs / config → developer → тесты → PR → владелец.

## Цели
| id | метрика | определение | база | цель | как |
|---|---|---|---|---|---|
| G1 | регистр | трудности копятся без владельца: записей в `friction.jsonl` за неделю | 0 | > 0, все виды из KINDS встречаются или объяснены | `team friction` |
| G2 | ретро | отчёты ретро за неделю пилота | 0 | ≥ 5 | `data/framework/retro/` |
| G3 | PR | pull request с зелёными тестами, открытых без владельца | 0 | ≥ 1 | GitHub |
| G4 | польза | доля предложений ретро, которые владелец признал полезными (merged или «да, но позже») | — | ≥ 50 % | ревью владельца |

## Разрешения
developer: Bash, Read, Edit, Write, Glob, Grep в чекауте; никакого деплоя. Diспетчер: push ветки, открытие PR. Merge — владелец.
