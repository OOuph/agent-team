## Что это
Ежедневный трекер принятия инструкций для кодовых агентов в open-source: у каких из ~2 000 самых звёздных публичных репозиториев GitHub (топ по звёздам внутри каждого из 10 языков) есть `AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `.cursor/rules/`, `.github/copilot-instructions.md`, `llms.txt`, `GEMINI.md`, `.windsurfrules`. Главная страница — крупные числа «N из M репо (x %) имеют AGENTS.md» и то же по остальным типам, график по дням, лента «сегодня добавили», таблица по языкам; карточка на каждый репозиторий; `stats.json`, `today.json`, RSS новых `AGENTS.md`, `llms.txt`. Публикуется только факт наличия файла, его размер и ссылка на GitHub — содержимое файлов не републикуется.

## Что обещаем и чего не обещаем
- На каждой странице (в подвале): «Built by AI agents (agent-team) without human editing · responsible: Dmitry, formachines.ai · updated <UTC>». Никакого сбора персональных данных, форм, cookies, JavaScript, трекинга людей; клики по внешним ссылкам считаются только по стандартному access-логу сервера через страницы-редиректы `/go/<id>/`.
- Адреса страниц не меняются: `/`, `/repo/<owner>/<name>/` (+ `index.json`), `/go/<id>/`, `/stats.json`, `/today.json`, `/feed.xml`, `/llms.txt`, `/legal/`, `/build.json`. Карточка репозитория остаётся, даже если репозиторий переехал или удалён (показывается статус).
- Данные датированы (`generated` / `built_at` в каждом JSON, дата у каждого числа на странице); источник каждого числа назван: публичный GitHub (Search API для выборки, HEAD-запросы к публичным URL файлов для наличия и размера). Статистика и JSON — CC BY 4.0; `/legal/` называет ответственного и ссылается на https://formachines.ai/legal/.
- Если данные не удалось обновить (лимит GitHub, сеть), сайт показывает последний удачный срез с пометкой «данные задерживаются» — не нули.
- **Чего не делаем:** не скачиваем, не храним, не цитируем и не републикуем содержимое файлов (`AGENTS.md` и прочих) — только ссылки на GitHub; не публикуем «примеры хороших файлов»; не ранжируем и не оцениваем репозитории и их авторов; не делаем выводов о качестве проектов; не заводим аккаунтов и форм на сайте; не меняем выборку задним числом (репо только добавляются, удаление — по просьбе мейнтейнера через `/legal/`).

## Ежедневная работа команды
- **04:00 UTC — скан и публикация:** `python3 build.py` на сервере обходит выборку (HEAD-запрос на каждый из 8 путей, один поток, без токена), пишет `data/scan/`, `data/history/<дата>.json`, собирает `public/`, коммит и push в `main`; droplet публикует через ≤ 5 минут. «День без свежего `data/history/<сегодня>.json` и без обновлённого `updated` в подвале = дефект».
- **Лента «добавили сегодня»:** путь, который есть сегодня и отсутствовал в предыдущем снимке того же репо; первый скан репо — базовая линия, не «добавление». Лента пуста два дня подряд → PO ставит задачу **расширить выборку** (следующие 100 по звёздам в языке, новые языки, топ по свежим коммитам `pushed:>дата` при `stars:>300`) — это главный рычаг против риска «топ по звёздам стабилен, прирост 0–3 в день».
- **Новые конвенции:** появление новой конвенции у инструментов агентов (как `GEMINI.md`, `.windsurfrules`) → одна запись в `PATHS` в `build.py`; старые дни истории считают её нулём.
- **QA (ревьюер):** ссылки на файлы живые (выборочно 10 `/go/` в день), язык репо верный, нет дублей и форков, таблицы читаются на 375 px, подвал с раскрытием ИИ на каждой странице, `data_delayed` в `build.json` = false.
- **Аналитик:** внешние клики на GitHub (`/go/`), какие карточки читают, referer; запросы `/stats.json`, `/today.json`, `/feed.xml` не от нас; возвраты. Источник — `metrics.json` (`sitemetrics`, 00:30 UTC).
- **Маркетолог:** ежедневный пост «+N репо с AGENTS.md за сутки, всего x % из M» в разрешённые каналы (числа — только из `today.json` / `stats.json` текущего дня, ссылка на сайт); один еженедельный срез на dev.to; тест формата (число против графика) — по решению PO.

## Глубина доработок (решение владельца 02.11: разрешено до L3)
| Уровень | Что | Кто решает |
|---|---|---|
| L0 | данные обновляются каждый день; день без обновления — дефект P1 | PO автоматически |
| L1 | исправления дефектов, найденных персонами, ревьюером, аналитиком, обратной связью | PO автоматически |
| L2 | небольшие функции из наблюдений: фильтры, страницы, срезы RSS/JSON, ссылки голосования и обратной связи | PO автоматически |
| L3 | доставка машинам: MCP-обёртка поверх существующих JSON (по образцу errata-mcp), публикация в реестр MCP и npm, llms.txt | PO автоматически |
| L4 | новые источники данных, новые продукты, аккаунты, платное, отдельный серверный API | только владелец |

## Разрешения ролей (решение владельца)
Разработчик: код и контент в репозитории, коммит на ветку задачи · Диспетчер: merge и публикация автоматически после самопроверки; откат при провале ревью · PO: задачи внутри этого файла — расширение выборки, новые конвенции в `PATHS`, формат ленты и постов · Маркетолог: публикует сам в каналах выше · Аналитик: читает `metrics.json`, пишет наблюдения · Только владелец: смена целей, каналов, бюджета, обещаний; новые аккаунты, домены, токены (`GITHUB_TOKEN` на сервере — опционален, скан работает без него); решение о X и Reddit; удаление репозитория из выборки по просьбе мейнтейнера.
